## 1. 系统设计

### 1.1 总体架构

```
浏览器（静态 HTML + 原生 JS）
   │  HTTP + JSON，请求头 Authorization: Bearer <JWT>
   ▼
FastAPI
   ├─ routers/   路由层：参数解析、鉴权、HTTP 状态码
   ├─ services/  业务层：问卷管理、提交、统计
   ├─ engine/    规则引擎：校验引擎、跳转引擎（纯函数，不访问数据库）
   └─ db.py      PyMongo 连接
   ▼
MongoDB：users / surveys / responses / participations
```

- 登录用 JWT，无状态，不需要另外的会话存储（满足 C1、C2，对应 X15）。
- 校验规则和跳转规则以**数据**形式存在问卷文档里。引擎只是通用的解释器，按题型和 op 查表执行，不为某份问卷写专门代码（满足 C8、D3）。

### 1.2 代码结构

```
app/
  main.py            创建应用，挂载路由和静态页面
  config.py  db.py
  security.py        bcrypt 密码哈希；JWT 签发与校验
  deps.py            "当前登录用户"依赖
  models.py          请求 / 响应的 Pydantic 模型
  routers/           auth.py  surveys.py  questions.py  fill.py  stats.py
  services/          surveys.py  submissions.py  stats.py
  engine/            validation.py  jump.py
db/
  schema.py          四个集合的 $jsonSchema 与索引（即提交物中的 MongoDB schema）
  init_db.py         建集合、更新校验器、建索引；可重复执行
static/              login.html  surveys.html  edit.html  fill.html  stats.html（含 js / css）
tests/
docs/
```

### 1.3 角色与权限

| 操作 | 谁可以 |
|---|---|
| 注册、登录 | 任何人 |
| 创建问卷；管理自己的问卷；看统计 | 登录用户，且只能操作自己创建的问卷（F1.7、F6.7）。访问别人的问卷一律返回 404，不暴露问卷是否存在 |
| 打开问卷链接、填写、提交 | 任何登录用户（F2.7、X1）；问卷须为已发布且未过截止时间 |
| 看到答卷是谁填的 | 只有非匿名问卷的创建者能看到 |

### 1.4 问卷状态

```
          publish             close
 draft ───────────► published ───────► closed
                        ▲                 │
                        └──── reopen ─────┘
```

- **draft（草稿）**：可以增删改题目、设置跳转；不能填写。
- **published（已发布）**：可以填写。设了截止时间且已过 → 拒绝提交。"已截止"是用 `deadline` 和当前时间算出来的，不单独存一个状态：这样不需要定时任务去改状态，也不会出现状态和时间对不上。
- **closed（已关闭）**：拒绝提交，统计照常能看。
- **reopen（重新开放）**：适用于已关闭的问卷，也适用于已发布但已过截止时间的问卷。状态回到 published，并要求截止时间为空或在未来（X11）。
- **发布条件**：至少 1 道题；所有跳转规则合法。
- **发布后锁定（X10，2026-10-19 本人调整）**：发布即确定，标题、说明、题目、是否匿名、是否允许多次填写**全部不能再改**；发现问题就删除问卷、重新创建发布。只保留"控制收不收答卷"的操作：关闭、重新开放（重新开放时可以设新的截止时间）。
- **删除（2026-10-19 本人设计）**：任何状态的问卷都可以删除，已收到的答卷随之无法再查看。采用标记删除：在问卷上写入 `deletedAt`，之后列表不显示、链接打不开、统计看不到、不能再提交；数据仍留在库里。标记删除只改一个文档，不存在跨集合删到一半的问题，误删时管理员也能恢复。
- **状态切换以时间先后为准**：发布、关闭、重开、删除、修改草稿全部用"条件更新"——把"当前状态是否允许"和"修改"合成一条数据库命令（单文档原子操作），晚到的、已不满足条件的操作直接失败并返回原因，不会出现"判断时还是草稿、写入时已经发布"的情况。

### 1.5 填写与提交流程

1. 填写者登录后打开分享链接 `/survey/{slug}`，前端调用 `GET /api/fill/{slug}` 拿到问卷。
2. 每答完一题，前端调用 `POST /api/fill/{slug}/navigate`，带上目前的全部答案。服务端返回答题路径、下一题和当前错误，前端据此显示下一题或错误提示（F4.5、F5.2–F5.4）。**跳转逻辑只在服务端实现一份**，前端不重复实现。
3. 提交时调用 `POST /api/fill/{slug}/responses`，服务端依次：
   1. 检查问卷可以填写：状态为 published，且没过截止时间；
   2. 从第一题起，按跳转规则重新算出答题路径；
   3. 对路径上的题逐题校验：必答题没答、或答案不合规则 → 报错；答了路径外的题 → 拒绝（X8）；
   4. 在 participations 里登记（不允许多次填写时，由唯一索引拦截重复）；
   5. 写入 responses（匿名问卷不写 `respondentId`）；
   6. 返回 201，只返回提交时间（填写者不能查看自己的答卷）。
4. 打开链接时（2026-10-20 确认）：草稿 → 404，对外当作不存在；发布过又删除 → 410"问卷已删除"；已关闭 / 已截止 → 200，照常返回标题和说明，并标明不能填写及原因；问卷不允许多次填写且本人已填过 → 一打开就标明"你已经填写过这份问卷"。填写视图不返回跳转规则。
5. 关闭问卷与提交同时发生时，以提交时检查那一刻为准：问卷还开着就算数（两个集合无法用一条命令同时完成，本机也不支持跨集合事务）。

## 2. MongoDB 设计

### 2.1 集合划分（D1）

| 集合 | 存什么 | 一条文档代表 | 增长特点 |
|---|---|---|---|
| `users` | 账号 | 一个用户 | 慢 |
| `surveys` | 问卷，内嵌题目、选项、校验规则、跳转规则 | 一份问卷的完整定义 | 慢；单份文档大小有上限 |
| `responses` | 答卷，内嵌各题答案 | 一次提交 | 快，没有上限 |
| `participations` | 谁填过哪份问卷、填了几次 | 一个（问卷, 用户）组合 | 与填写人数同级 |

引用关系：

```
users._id ◄── surveys.ownerId
surveys._id ◄── responses.surveyId
users._id ◄── responses.respondentId     （仅非匿名问卷）
surveys._id, users._id ◄── participations.surveyId, participations.userId
```

### 2.2 嵌入还是引用（D4）

| 关系 | 选择 | 理由 |
|---|---|---|
| 问卷 → 题目、选项、规则 | 嵌入 | 打开、填写、校验、统计都需要整份定义，总是一起读；题目数量有限（几十道题只有几十 KB，远低于 16MB 上限）；发布后整体锁定，不存在单独高频修改某道题的情况；一次读取拿到全部，单文档更新天然是原子的 |
| 问卷 → 答卷 | 引用（`responses.surveyId`） | 答卷数量没有上限。嵌进问卷会让问卷文档无限增长、逼近 16MB；多人同时提交还会争抢同一个文档（F5.7） |
| 答卷 → 各题答案 | 嵌入 | 一次提交是一个整体：一次写入，一起读取 |
| 问卷 → 创建者 | 引用（`ownerId`） | 用户独立存在，一个用户对应多份问卷 |
| 谁填过 | 单独集合 `participations` | 匿名问卷的答卷不能带用户 id（X1），但创建者关闭多次填写时，"每人只能填一次"又必须知道谁填过（X3）。把"谁填过"和"填了什么"分开存，两边都只通过 surveyId 关联，无法把某个人对应到某份答卷 |

**冗余的取舍（D2）**

- 答卷只存题目 id 和选项 id，不复制题目标题和选项文字；统计展示时再从问卷文档取。这样做的前提是发布后题目结构锁定（X10），id 总能找到对应的题目和选项。
- 不在问卷文档里维护"已选人数"这类计数字段，统计时实时聚合。好处是多人同时提交不会争抢同一个文档，计数也不会和答卷对不上。代价是每次看统计都要扫一遍该问卷的答卷，课程规模下可以忽略；如果阶段二答卷量很大，再考虑预先计算。
- 唯一有意保留的重复是 `participations.count`。非匿名问卷的提交次数能从 responses 数出来，但匿名问卷的答卷里没有用户 id，数不出来，所以需要这个字段。

### 2.3 文档结构

所有文档都带 `schemaVersion`（当前为 1），以后结构变化时，迁移脚本按版本号升级（见 2.12）。

**users**

```js
{
  _id: ObjectId("..."),
  schemaVersion: 1,
  username: "zhangsan01",             // 账号：登录用，唯一，3–32 位字母 / 数字 / 下划线，区分大小写
  displayName: "张三",                 // 名字：展示用，可重复，1–32 个字符
  passwordHash: "$2b$12$...",         // bcrypt 哈希，不存明文（X14）
  createdAt: ISODate("2026-10-15T08:00:00Z")   // 注册时间（F1.6）
}
```

账号与名字分开（2026-10-19 本人设计）：账号对应原文的"用户名"，只用于登录并保证唯一；名字只用于展示，允许重名。需要区分重名的地方（如统计里的填写者）显示为"名字（账号）"。

密码规则（2026-10-19 本人设计）：8–72 位，只允许英文字母、数字和英文符号（可打印 ASCII 字符，不含空格），不能有汉字。上限 72 是 bcrypt 能处理的最大字节数；只允许 ASCII 字符后一个字符就是一个字节，所以 72 个字符正好用满。

**surveys**（示例题目取自作业原文）

```js
{
  _id: ObjectId("..."),
  schemaVersion: 1,
  revision: 7,                         // 修改版本号：每次修改加 1，写回时用作乐观锁条件（见 2.9）
  ownerId: ObjectId("..."),            // → users._id
  title: "大学生生活调查",
  description: "约 2 分钟",
  slug: "k3X9pQ2a",                    // 分享链接 /survey/k3X9pQ2a，8 位随机字母数字，唯一
  status: "published",                 // draft | published | closed
  settings: {
    allowAnonymous: false,             // F2.1
    allowMultipleSubmissions: true,    // X2：默认允许，创建者可以关闭
    deadline: ISODate("2026-11-01T00:00:00Z")  // 可为 null
  },
  questions: [
    {
      id: "q_a0000001", type: "single_choice", title: "你的性别", required: true,
      options: [
        { id: "o_b0000001", label: "男" },
        { id: "o_b0000002", label: "女" },
        { id: "o_b0000003", label: "其他" }
      ],
      jumpRules: [
        { when: { op: "eq", value: "o_b0000003" }, goto: "q_a0000004" }   // 选"其他"跳到第 4 题
      ]
    },
    {
      id: "q_a0000002", type: "multiple_choice", title: "你喜欢的水果", required: true,
      options: [
        { id: "o_c0000001", label: "苹果" }, { id: "o_c0000002", label: "香蕉" },
        { id: "o_c0000003", label: "西瓜" }, { id: "o_c0000004", label: "葡萄" }
      ],
      validation: { minSelect: 2, maxSelect: 3 }
    },
    {
      id: "q_a0000003", type: "number_input", title: "年龄", required: true,
      validation: { min: 0, max: 120, integer: true },
      jumpRules: [
        { when: { op: "lt", value: 18 }, goto: "END" }                     // 未成年直接结束
      ]
    },
    {
      id: "q_a0000004", type: "text_input", title: "你的建议", required: false,
      validation: { minLength: 5, maxLength: 200 }
    }
  ],
  createdAt: ISODate("..."), updatedAt: ISODate("..."),
  publishedAt: ISODate("..."), closedAt: null
  // 被删除的问卷另有 deletedAt: ISODate("...")；未删除的没有这个字段
}
```

**responses**

```js
// 非匿名问卷：路径 第1题 → 第2题 → 第3题 → 第4题
{
  _id: ObjectId("..."), schemaVersion: 1,
  surveyId: ObjectId("..."),           // → surveys._id
  respondentId: ObjectId("..."),       // → users._id；匿名问卷没有这个字段
  submittedAt: ISODate("..."),
  answers: [                           // 只含答题路径上实际作答的题，按路径顺序
    { questionId: "q_a0000001", value: "o_b0000001" },                  // 单选：选项 id
    { questionId: "q_a0000002", value: ["o_c0000001", "o_c0000003"] },  // 多选：选项 id 数组
    { questionId: "q_a0000003", value: 20 },                            // 数字
    { questionId: "q_a0000004", value: "希望食堂多开几个窗口" }          // 文本
  ]
}

// 匿名问卷：第1题选"其他"，按规则跳过第2、3题
{
  _id: ObjectId("..."), schemaVersion: 1,
  surveyId: ObjectId("..."),
  submittedAt: ISODate("..."),
  answers: [
    { questionId: "q_a0000001", value: "o_b0000003" },
    { questionId: "q_a0000004", value: "没有建议，谢谢" }
  ]
}
```

答案用 `[{questionId, value}]` 数组，而不是以题目 id 作键的对象 `{ "q_a0000001": ... }`：动态键名没法建索引、没法用校验器约束，聚合时也得先转换；数组可以直接 `$unwind` 后按 `questionId` 分组。

**participations**

```js
{
  _id: ObjectId("..."), schemaVersion: 1,
  surveyId: ObjectId("..."),
  userId: ObjectId("..."),
  count: 1                             // 该用户对该问卷的提交次数
}
```

### 2.4 题型与校验规则的存储

题型和原文的对应：原文的"填空题"分"文字或数字"两种，这里拆成 `text_input` 和 `number_input` 两个题型。这样每个题型的字段是固定的，校验器能逐个题型约束。

| `type` | 原文 | `options` | `validation` 字段 | 答案 `value` |
|---|---|---|---|---|
| `single_choice` | 单选题 | ≥ 2 个 | 无 | 选项 id（字符串） |
| `multiple_choice` | 多选题 | ≥ 2 个 | `minSelect`、`maxSelect` | 选项 id 数组，不重复 |
| `text_input` | 文本填空 | 无 | `minLength`、`maxLength` | 字符串 |
| `number_input` | 数字填空 | 无 | `min`、`max`、`integer` | 数字 |

所有题型都有 `required`（F3.6）。

- **必答**：`required: true` 表示该题在答题路径上就必须作答。`required: false` 可以不答，但一旦作答，答案就要满足 `validation`。
- **多选数量**："至少 2 个 / 最多 3 个 / 必须 2 个"分别存成 `minSelect: 2` / `maxSelect: 3` / `minSelect: 2, maxSelect: 2`。两个字段就能表达三种需求，也不会出现"必须 2 个又至少 3 个"这种矛盾组合。
- **字数**：按字符数计，一个汉字算 1。
- **手机号**（X13）：用 `number_input` 加 `integer: true`。11 位数超过 32 位整数范围，存为 64 位整数，已验证可行。
- **保存题目时应用层还要检查**：选项 id 不重复；`minSelect ≤ maxSelect ≤ 选项数`；`min ≤ max`；`minLength ≤ maxLength`。
- **校验引擎**：两张对照表。一张按 `type` 找到答案类型检查，另一张按 `validation` 的每个键找到对应检查函数；错误信息用中文，按题目 id 返回。

### 2.5 跳转规则的存储与求值

跳转规则存在**来源题**上：`jumpRules` 数组，每条为 `{ when: { op, value }, goto }`。`goto` 是目标题的 id，或者 `"END"`（结束问卷）。

| 题型 | `op` | `value` | 命中条件 |
|---|---|---|---|
| 单选 | `eq` | 选项 id | 选了这个选项 |
| 单选 | `in` | 选项 id 数组 | 选了其中任一个 |
| 多选 | `containsAny` | 选项 id 数组 | 至少选了其中一个 |
| 多选 | `containsAll` | 选项 id 数组 | 这些全都选了 |
| 多选 | `equals` | 选项 id 数组 | 选的恰好就是这些 |
| 数字 | `eq` `ne` `gt` `gte` `lt` `lte` | 数字 | 等于 / 不等于 / 大于 / 大于等于 / 小于 / 小于等于 |
| 数字 | `between` | `[a, b]` | a ≤ 值 ≤ b |
| 文本 | — | — | 不支持跳转（F4 只要求单选、多选、数字） |

原文例子"第 1 题选 A → 跳到第 5 题；选 B → 跳到第 3 题"存成：

```js
jumpRules: [
  { when: { op: "eq", value: "<A 的选项 id>" }, goto: "<第 5 题的 id>" },
  { when: { op: "eq", value: "<B 的选项 id>" }, goto: "<第 3 题的 id>" }
]
```

**求值方法**

1. 从第一题开始。
2. 当前题如果作答了，按 `jumpRules` 的顺序逐条判断，**第一条命中的生效**，跳到它的 `goto`。
3. 没有规则命中，或者这题没作答 → 进入顺序上的下一题。
4. `goto` 是 `END`，或已经过了最后一题 → 结束。
5. 走过的题组成"答题路径"；必答检查和答案校验只针对路径上的题。

**保存规则时检查（应用层）**：`goto` 指向的题存在，且位于来源题**之后**（只能往后跳，因此不会形成死循环，X7）；`value` 里的选项 id 都属于本题；`between` 的 a ≤ b。`op` 与题型是否匹配，数据库校验器也会检查。

**整份检查**（`app/engine/structure.py` 的 `check_survey`）：每次修改题目写回前、以及发布前，都对整份问卷检查一遍题目定义和全部跳转规则，错误信息指明"第几题、第几条规则、什么问题"。

**修改会让已有规则失效时，一律拒绝并说明原因，不自动改动用户的配置**（2026-10-20 确认）：

| 操作 | 什么情况下拒绝 | 状态码 |
|---|---|---|
| 设置跳转规则 | 规则本身不合法（往前跳、目标不存在、条件与题型不匹配、用了别的题的选项等） | 422 |
| 删除题目 | 有别的题的规则跳到它，提示是哪几道题 | 409 |
| 调整顺序 | 某条规则因此变成往前跳 | 409 |
| 修改题目 | 删掉的选项被本题规则用到；或本题已有规则时改题型 | 409 |

修改题目时，原有选项提交时带上 id、新选项不带，服务器保留原 id，因此改选项文字不影响规则。

**填写时的答案约定与引擎**（2026-10-20 确认，实现见 `app/engine/validation.py`、`app/engine/jump.py`）

- 填写页一题一页。答案以 `{题目 id: 值}` 传给引擎：**没有这道题 = 还没答到**；值为 `null`、空字符串或空数组 = 看过、不答（非必答题点"下一题"时传 `null`，必答题会提示"此题为必答题"）。
- 校验引擎按题型查表检查。数字只接受数字类型，`"18"` 这样的字符串不接受；要求整数时 `18.0` 视为 18；文本去掉首尾空格后计字数（一个汉字算 1），只有空格视为不答；多选重复选同一项报错，保存时按选项原本的顺序排列。
- 跳转引擎按上面的求值方法走路径。已答的题不合规时，路径停在这道题（答案不对就无法决定往哪跳）。
- 两个入口：
  - `navigate`（填写过程中）：返回路径、下一题、已答题的错误。改了前面的答案导致后面的答案不在路径上时，只把这些题列出来提示前端清掉，不算错误。
  - `evaluate_submission`（提交时）：从头重算，路径上没传的题按"不答"处理；答了路径外的题、不存在的题都记为错误；全部通过才保存，只保存路径上实际作答的题。

**为什么这样存**

- 规则是问卷定义的一部分：和题目一起读取、一起锁定，放在来源题上最直观。
- 用题目 id 而不是题号（X9）：插入题目或调整顺序后，规则不会失效。
- `when` 是扩展点：如果阶段二要求"第 1 题选 A 且第 3 题大于 5"，可以扩展成 `when: { all: [ {questionId, op, value}, ... ] }`，引擎加一个组合判断即可，现有规则照样有效。

### 2.6 索引

| 集合 | 索引 | 类型 | 服务的查询 |
|---|---|---|---|
| users | `{ username: 1 }` | 唯一 | 登录时按账号查找；保证账号不重复 |
| surveys | `{ slug: 1 }` | 唯一 | 通过分享链接打开问卷；保证链接不重复 |
| surveys | `{ ownerId: 1, createdAt: -1 }` | 普通 | "我的问卷"列表：按创建者过滤、按时间倒序，一个索引同时覆盖过滤和排序 |
| responses | `{ surveyId: 1, submittedAt: -1 }` | 普通 | 统计聚合的 `$match`；填空题内容按时间分页 |
| participations | `{ surveyId: 1, userId: 1 }` | 唯一 | 判断某人是否填过；并发提交时由唯一约束防止重复 |

暂不对 `answers.questionId` 建多键索引：统计总是先按 `surveyId` 过滤，单份问卷的答卷量在课程规模下很小。

### 2.7 校验器：两层分工

| 层 | 负责 | 例子 |
|---|---|---|
| 数据库（`$jsonSchema`，`validationLevel: "strict"`，`validationAction: "error"`） | 结构与类型 | 必填字段、字段类型、状态枚举、id 格式；题型与字段的对应（按 `type` 用 `oneOf` 分支）；跳转 `op` 必须与题型匹配；文本题不能有跳转规则；答案值只能是字符串、数字或数组 |
| 应用层 | 跨字段、跨文档、依赖具体问卷的语义 | `minSelect ≤ maxSelect`；选项 id 唯一；`goto` 指向存在且靠后的题；答卷内容是否满足该问卷各题的规则（每份问卷规则不同，数据库校验器无从得知） |

两层都要：数据库校验器是最后一道防线，挡住程序 bug 或手工在 mongosh 里写入的坏数据；应用层负责给用户友好的逐题错误提示。

### 2.8 统计（F6）

整份问卷的统计用一次聚合完成（已在临时库中跑通）：

```js
db.responses.aggregate([
  { $match: { surveyId: <问卷 id> } },
  { $unwind: "$answers" },
  { $facet: {
      // 每道题有多少份答卷作答了
      answered: [
        { $group: { _id: "$answers.questionId", n: { $sum: 1 } } }
      ],
      // 选择题每个选项被选次数（单选的值是字符串，$unwind 当作单元素处理；多选的值是数组，被展开）
      optionCounts: [
        { $match: { "answers.questionId": { $in: <选择题 id 列表> } } },
        { $unwind: "$answers.value" },
        { $group: { _id: { q: "$answers.questionId", o: "$answers.value" }, n: { $sum: 1 } } }
      ],
      // 数字题平均值
      numberAvg: [
        { $match: { "answers.questionId": { $in: <数字题 id 列表> } } },
        { $group: { _id: "$answers.questionId", avg: { $avg: "$answers.value" }, n: { $sum: 1 } } }
      ]
  } }
])
```

- 另用 `countDocuments({ surveyId })` 得到问卷的总提交数。
- 应用层把聚合结果和问卷定义合并：补上选项文字，没人选的选项补 0。
- 填空题内容按单题分页查询：`$match` → `$unwind` → 按题目过滤 → 按提交时间倒序 → `$skip` / `$limit`。非匿名问卷再 `$lookup` users，带上填写者的"名字（账号）"。
- **统计口径（X12）**：单选的"回答人数"指作答了这道题的答卷数（因为有跳转，可能少于问卷总提交数），同时给出问卷总提交数；多选是每个选项被选的次数。

### 2.9 并发与一致性

- **多人同时填写（F5.7）**：每次提交只插入一条新文档，不修改任何共享文档（问卷里没有计数字段），所以没有写冲突。
- **多次填写（F5.9、X2）**：默认允许。这时每次提交都直接记一条答卷，participations 只把该用户的 `count` 加 1，不做任何拦截。
- **创建者关闭了多次填写时**：靠 participations 的唯一索引防止同一人重复提交。两个请求同时提交时，只有一个能插入成功，另一个收到重复键错误（E11000），返回"已填写过"。
- **两步写入没有放进事务**（只影响关闭了多次填写的问卷）：本机 MongoDB 默认以单机模式运行，不支持多文档事务（事务需要副本集）。做法是先登记 participations，再写 responses；写 responses 失败就撤回登记（删除，或把 `count` 减 1）。最坏情况是进程恰好在两步之间崩溃，结果是"登记了但没有答卷"，不会出现重复答卷。改用单节点副本集就能用事务，见第 3 节第 5 条。
- **发布后结构锁定**：保证统计时的题目定义与答卷一致。
- **编辑题目用乐观锁**（2026-10-20 确认）：题目之间有引用，检查要看整份问卷，所以题目的增、改、删、调序、设规则都按"读出问卷 → 代码里修改 → 整份检查 → 写回"进行。写回时带上条件 `revision` 等于读出时的值，并把 `revision` 加 1；如果中间有别的修改插进来，`revision` 已变，写回失败，返回"问卷刚被修改过，请刷新后重试"。发布同样带 `revision` 条件，保证发布的正是刚检查过的那一版。这样不需要锁住问卷，也不需要事务，就能做到"以先到者为准"。

### 2.10 为什么不用关系数据库的结构（D5）

同样的数据放进关系库，至少需要：users、surveys、questions、options、jump_rules（及条件表）、responses、answers，以及多选用的 answer_options。问题在于：

- **打开问卷**：一份问卷要 join 四五张表，再在应用层拼回树形结构。
- **题型字段不同**：要么 questions 表里大量可空列（min_select、max_length、min_value、is_integer……），要么每种题型一张表；新增题型就得改表结构。
- **答案类型不同**：值可能是选项、数组、文本或数字，要么拆成多列（value_text / value_number / option_id），要么用 EAV（实体-属性-值）模式；统计 SQL 会很绕。
- **多选答案**：一个值是数组，只能拆到子表。

在 MongoDB 里，一份问卷就是一个文档，读写方式和使用方式一致；答案的值天然可以是多种类型，数组直接存。

### 2.11 为什么适合 MongoDB（D6）

- **结构匹配**：问卷是树形的、按题型变化的结构。文档模型加数组嵌入，一次读写就能拿到或存下整份问卷。
- **灵活又可约束**：灵活的 schema 允许不同题型有不同字段，`$jsonSchema` 校验器又能在数据库层把结构管住。
- **统计在库内完成**：聚合管道（`$unwind` / `$group` / `$facet` / `$lookup`）可以直接在数据库里算统计。
- **适应需求变化**：阶段二新增字段不用停机改表。每个文档带 `schemaVersion`，可以按版本逐步迁移（Schema Versioning 模式）。
- **写入模式合适**：答卷只追加、不修改，适合高并发插入。

### 2.12 为阶段二预留的扩展点

- **`schemaVersion`**：结构变化时，迁移脚本按版本升级；迁移期间可以把校验器临时设为 `validationLevel: "moderate"`。
- **新题型**：校验器 `oneOf` 加一个分支，校验引擎、跳转引擎、统计各加一个函数，已有数据不受影响。
- **跳转条件**：可以按 2.5 末尾说的方式扩展成组合条件。
- **稳定 id**：题目和选项的 id 不随顺序变化。如果阶段二要把题目抽成独立集合（比如题库），可以直接沿用。
- **git tag**：阶段一提交时打 tag，阶段二报告中的"改了哪些部分"可以直接对照 diff 说明。

## 附录 A：`$jsonSchema` 校验器全文

与附录 B 实测时使用的定义一致（mongosh 语法）。实现时会原样移到 `db/schema.py`。

```js
const QID = "^q_[0-9a-f]{8}$";
const OID = "^o_[0-9a-f]{8}$";

const options = {
  bsonType: "array", minItems: 2,
  items: {
    bsonType: "object", required: ["id", "label"],
    properties: {
      id: { bsonType: "string", pattern: OID },
      label: { bsonType: "string", minLength: 1, maxLength: 200 },
    },
  },
};
// 按题型限制跳转规则可用的 op
const rulesWithOps = (ops) => ({
  items: { properties: { when: { properties: { op: { enum: ops } } } } },
});

const question = {
  bsonType: "object",
  required: ["id", "type", "title", "required"],
  properties: {
    id: { bsonType: "string", pattern: QID },
    type: { enum: ["single_choice", "multiple_choice", "text_input", "number_input"] },
    title: { bsonType: "string", minLength: 1, maxLength: 500 },
    required: { bsonType: "bool" },
    validation: { bsonType: "object" },
    jumpRules: {
      bsonType: "array",
      items: {
        bsonType: "object", required: ["when", "goto"],
        properties: {
          when: { bsonType: "object", required: ["op", "value"], properties: { op: { bsonType: "string" } } },
          goto: { bsonType: "string", pattern: "^(q_[0-9a-f]{8}|END)$" },
        },
      },
    },
  },
  oneOf: [
    { required: ["options"],
      properties: {
        type: { enum: ["single_choice"] },
        options: options,
        jumpRules: rulesWithOps(["eq", "in"]),
      } },
    { required: ["options"],
      properties: {
        type: { enum: ["multiple_choice"] },
        options: options,
        validation: { bsonType: "object", properties: {
          minSelect: { bsonType: "int", minimum: 0 },
          maxSelect: { bsonType: "int", minimum: 1 },
        } },
        jumpRules: rulesWithOps(["containsAny", "containsAll", "equals"]),
      } },
    { properties: {
        type: { enum: ["text_input"] },
        validation: { bsonType: "object", properties: {
          minLength: { bsonType: "int", minimum: 0 },
          maxLength: { bsonType: "int", minimum: 1 },
        } },
        jumpRules: { maxItems: 0 },
      } },
    { properties: {
```
